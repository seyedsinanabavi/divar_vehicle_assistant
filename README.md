# دستیار بررسی آگهی خودرو دیوار (Python)

این پروژه هسته‌ی قابل اجرا برای خواندن فهرست آگهی‌ها، فیلتر خودرو، ثبت سابقه و جلوگیری از پردازش تکراری را فراهم می‌کند.
اتصال واقعی به حساب دیوار و ارسال پیام عمداً به‌صورت ساختگی پیاده‌سازی نشده؛ باید از مسیر رسمی و مجاز با مستندات واقعی تکمیل شود.

## نیازمندی
- Python 3.10 یا بالاتر
- کتابخانه‌ها: فقط استاندارد پایتون (بدون نیاز به نصب بسته خارجی)

## اجرا
در پوشه پروژه:

```bash
python -m divar_bot.cli --csv sample_listings.csv
```

بار اول در حالت آزمایشی اجرا می‌شود و پیام واقعی نمی‌فرستد. خروجی و دیتابیس را بررسی کنید.

نمایش آمار:

```bash
python -m divar_bot.cli --stats
```

## قالب CSV
ستون‌های موردنیاز:
- `listing_id`: شناسه یکتای آگهی
- `title`: عنوان آگهی
- `url`: لینک آگهی
- `price`: قیمت عددی به ریال (اختیاری)
- `city`: شهر (اختیاری)
- `description`: توضیحات (اختیاری)
- `chat_available`: `true`، `false` یا خالی اگر نامشخص است
- `published_at`: زمان انتشار (اختیاری)

## تنظیمات
متغیرهای محیطی را می‌توانید تنظیم کنید؛ نمونه در `.env.example` آمده است. برنامه به طور پیش‌فرض در حالت `DRY_RUN` می‌ماند.

## وضعیت‌ها
- `dry_run`: فقط شبیه‌سازی؛ ارسال واقعی انجام نشده
- `sent`: اتصال واقعی گزارش موفقیت داده
- `send_failed`: اتصال واقعی ارسال را ناموفق گزارش کرده
- `chat_unavailable`: چت غیرفعال است
- `needs_chat_check`: وضعیت چت مشخص نیست، بنابراین پیام ارسال نمی‌شود
- `filtered_out`: با فیلترها مطابقت ندارد
- `error`: خطا هنگام پردازش

## تکمیل اتصال دیوار
کلاس `DivarProvider` در `divar_bot/provider.py` رابط اتصال است. یک پیاده‌سازی واقعی باید:
1. فقط از روش ورود و API مجاز و مستند استفاده کند.
2. وضعیت امکان چت را از داده معتبر دریافت کند.
3. نتیجه ارسال را فقط پس از تأیید سرویس موفق اعلام کند.
4. محدودیت نرخ درخواست‌ها و خطاهای احراز هویت را رعایت کند.
5. از ارسال انبوه ناخواسته یا دور زدن سامانه‌های ضدسوءاستفاده خودداری کند.

نکته: `ManualImportProvider` نمونه‌ی قابل اجرا برای تست است؛ خودش وارد دیوار نمی‌شود و پیام نمی‌فرستد.


## ورود رسمی به حساب از طریق OAuth (اضافه شد)

ورود با نام کاربری/رمز یا خواندن کد پیامک به‌صورت خودکار انجام نمی‌شود. این ماژول کاربر را به صفحه رسمی OAuth دیوار هدایت می‌کند؛ کاربر آنجا وارد می‌شود و دسترسی‌ها را تأیید می‌کند.

1. در پنل توسعه‌دهندگان «کنار دیوار» برنامه بسازید.
2. `client_id` (slug)، `client_secret` و یک `redirect_uri` مجاز تنظیم کنید.
3. مقادیر را در متغیرهای محیطی قرار دهید (نمونه در `.env.example`).
4. اجرا کنید:
   ```bash
   python -m divar_bot.oauth_login login
   ```
5. برای تازه‌سازی توکن:
   ```bash
   python -m divar_bot.oauth_login refresh
   ```

مقادیر لازم در Windows PowerShell:
```powershell
$env:DIVAR_CLIENT_ID="slug-app"
$env:DIVAR_CLIENT_SECRET="secret-from-kenar"
$env:DIVAR_REDIRECT_URI="http://127.0.0.1:8765/callback"
$env:DIVAR_OAUTH_SCOPES="offline_access"
python -m divar_bot.oauth_login login
```

**مهم:** `DIVAR_REDIRECT_URI` باید دقیقاً در پنل کنار ثبت شده باشد و با آدرسی که در OAuth درخواست می‌شود یکی باشد. اگر کنار آدرس loopback را قبول نکند، باید callback را روی یک آدرس HTTPS که خودتان کنترل می‌کنید پیاده کنید.

این مرحله فقط احراز هویت و گرفتن توکن را انجام می‌دهد؛ به‌خودی‌خود اجازه ارسال پیام به همه آگهی‌دهندگان را نمی‌دهد. طبق مستندات کنار، ارسال پیام به یک مکالمه نیازمند scope `CONVERSATION_SEND_MESSAGE.<conversation_id>` و مجوز لازم برای برنامه است. دسترسی به هر مکالمه باید از طرف دیوار اعطا شود. همچنین مستندات دیوار استفاده از پیام برای تبلیغ یا معرفی خدمات را منع می‌کند.
